# Decisions and open questions

A rolling log of choices made for agentcurfew and questions still waiting for a verified answer. Each entry is tagged `D-NNN`; open questions use `Q-NNN`.

## D-001: Project layout mirrors depcurfew
- **Date:** 2026-11-06
- **Decision:** ESM-only TypeScript, `tsdown`, Vitest, `publint`, `@arethetypeswrong/cli`, two binaries (`agentcurfew`, `acf`), per-agent knowledge modules in `src/knowledge/`, docs in `docs/`.
- **Why:** Contributors already know the depcurfew shape, and the two projects stay visibly a family.

## D-002: Argument parser is `node:util` `parseArgs`
- **Date:** 2026-11-06
- **Decision:** Use the standard library parser instead of a dependency.
- **Why:** The plan asks for it, and it keeps the runtime dependency list empty. It is available from Node 18.3, the `engines` floor. Its stability level on Node 18 was not checked, and the floor itself has only been run on Node 25.8.1 so far (see Q-004).

## D-003: CLI alias `acf`
- **Date:** 2026-11-06
- **Decision:** Ship `agentcurfew` and the short alias `acf`, as depcurfew does with `dcf`, subject to the check in Q-001.

## D-004: No runtime dependencies yet
- **Date:** 2026-11-06
- **Decision:** `yaml` is not declared until code imports it.
- **Why:** The plan allows at most `yaml`, and CLAUDE.md allows it only when needed. An unused dependency in a security tool is attack surface with no benefit.

## D-005: Tool versions follow the repository's own 7-day cooldown
- **Date:** 2026-11-06
- **Decision:** Exact pins, checked against the npm registry on this date, at the newest version at least 7 days old: `@types/node` 26.6.6, `fast-check` 4.10.2, `publint` 0.3.25, `@arethetypeswrong/cli` 0.18.5. `tsdown` stays at 0.23.2 and `vitest` at 5.0.5, because 0.23.5 and 5.1.0 were 2 and 3 days old.
- **TypeScript:** stays at 6.0.3, matching depcurfew, although 7.0.2 is out and old enough. A major version of the compiler is a choice for both projects together, and it was not tried here (see Q-005).

## D-006: The repository follows its own depcurfew policy
- **Date:** 2026-11-06
- **Decision:** `depcurfew.json` copies the strict policy of the depcurfew repository (7-day delay, scripts denied, all non-registry sources denied). `.npmrc` is generated by `depcurfew apply`, and `packageManager` pins npm 11.21.1 so that it is generated for the version in use.
- **Note:** `depcurfew` is not a dev dependency. `apply` and `doctor` were run from the current depcurfew source. Phase 9 needs a real way to run `dcf doctor` in CI.

## D-007: `allowScripts` keeps depcurfew's `fsevents: false`
- **Date:** 2026-11-06
- **Decision:** Same entry as in depcurfew's `package.json`; `fsevents` is a macOS-only optional dependency of the test tooling.

## Q-001: Does `acf` collide with a common tool in PATH?
- **Status:** open, answered in phase 1 as the plan's first-session prompt asks.

## Q-002: Is the name `agentcurfew` still free on npm?
- **Status:** free on 2026-11-06 (`npm view agentcurfew` returns E404). Check again right before the first publish.

## Q-003: Separate `@agentcurfew/mcp` package?
- **Status:** open until phase 7, depending on whether the MCP server needs the SDK.

## Q-004: Is Node 18.3 really the floor?
- **Status:** open. Taken from depcurfew. The build tool does not support every Node version at build time (`rolldown-plugin-dts` warns on 25.8.1, though it builds), and the output has only been run on 25.8.1. A CI matrix should settle the floor in phase 6 or 9.

## Q-005: TypeScript 7?
- **Status:** open, maintainer's choice. `tsdown` 0.23.5 declares `^7.0.0` as a supported peer; whether 0.23.2 and the d.ts build work with it was not tested.
